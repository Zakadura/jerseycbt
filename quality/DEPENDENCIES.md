# Dependency assessment — 8 September 2026

Node is pinned to supported 24.20.0, with @types/node 24.13.3. Astro remains on its compatible 5.x line at 5.18.2, RSS on 4.0.19, with Astro Check 0.9.10 and TypeScript 6.0.3. The missing generated Astro declarations were added to tsconfig; no speculative TypeScript downgrade was needed. Matching lockfile install, strict checks and static build are required.

The initial M1 audit reported 22 affected package entries. Adding the mandated browser/performance tools initially raised the count to 40; compatible transitive fixes reduced it to 33 (9 high, 20 moderate, 4 low, no critical). Counts include dependent packages, not distinct exploits. The raw audit remains local evidence. No forced major upgrade, downgrade or override was used. Compatible updates include Vite, PostCSS, Browserslist, YAML, Nanoid, selector parser and SVGO. Remaining entries fall into the following eight source-advisory families; parent entries inherit those findings.

| Family | Reachability in this project | Disposition |
|---|---|---|
| Astro rendering / server advisories | Static output, no server adapter, server islands, define:vars or view transitions. Generic CTA spread props come from reviewed local templates, with no user-controlled attribute/slot names. JSON-LD text explicitly escapes `<`. | No identified public exploit path in this build. Retain a planned Astro major compatibility migration; reassess before adding server rendering or untrusted content. |
| Sharp / libvips | Build-time image processing of the existing repository portrait and checked local assets; no public image upload or runtime image server. | Existing trusted assets only. New untrusted image ingestion is blocked pending patched-image-tool compatibility work. |
| esbuild Windows development server | Build tooling, not emitted client code. The quality server is a small independent static server bound to loopback. | Do not expose the Astro/Vite/esbuild development server to a network. Reassess the compatible bundler upgrade with Astro migration. |
| extract-zip via Puppeteer/Lighthouse | Browser downloader helper. No patched extract-zip version is currently reported. Lighthouse uses preinstalled Chrome; its downloader is not invoked by the checks. Playwright uses its own browser installer. | Do not feed arbitrary archives to this helper. Preserve the comparable Lighthouse version until a reviewed measurement migration; avoid claiming the advisory was fixed. |
| tmp via Lighthouse CI / external-editor | Local CLI temporary-file paths. The used LHCI command is noninteractive `assert` over local reports; no external-editor or user-supplied path options. | No public input path. Keep reports in the isolated checkout. Reassess maintained CLI migration rather than accepting npm's suggested downgrade to LHCI 0.1.0. |
| UUID via Lighthouse CI | Tooling dependency; no website use of its vulnerable buffer-writing variants. | No identified reachable untrusted buffer input in the selected assertion path. Track CLI migration. |
| OpenTelemetry / Sentry via Lighthouse | Tooling instrumentation; no server accepting public W3C baggage in this static website or test server. | Local controlled URLs only; no telemetry instrumentation ships in the website. Track Lighthouse upgrade with a new comparable reference. |
| qs via Express/body-parser in tooling | No Express server is run by the quality commands; production is static and forms submit directly to Formspree. | No identified public parsing path. Track the upstream ranges; do not force an unreviewed transitive override. |

This is a bounded local reachability assessment, not a zero-vulnerability claim or approval to accept new exposure. Codex owns follow-up at M3 dependency/content changes and before release; rerun audit then and revisit every family if architecture/input sources change. Remaining tooling risk and migration work remain in the release notes. Future public PR jobs have read-only tokens and no production secrets.
