## Interactions and evidence limits

Synthetic Formspree fixtures cover accepted `{ok:true}`, field rejection `{errors:[{field,code,message}]}`, captcha/plan-style rejection, 5xx, invalid JSON, unknown 2xx, dropped network and timeout. Unknown or ambiguous receipt retains input and warns before a manual retry; no automatic duplicate sends. A genuine provider success is required to show acceptance. These fixtures prove local recovery, not this account's current API acceptance or delivery. M3 must verify both enhanced JSON and native action/method paths, allowed domains/captcha/plan settings and delivery to an owner-authorized test destination.

Calendly has one shared asset promise, explicit inline initialization, concurrent consumer tests, timeout/failure/retry and direct/email alternatives. The synthetic API records calls only; it does not certify the provider dialog's focus management, iframe availability or appointment completion. M3 owns real account and whole-journey checks without creating unauthorized bookings.

The sticky preference is a session-only dismissal; storage failure falls back to memory. Hidden controls are inert, the bar hides during form entry and on the booking route, and there is no required motion. Ordinary keyboard navigation can reach both booking and dismiss controls. Space below the footer follows the rendered bar height, including larger text, while the mobile reminder is eligible. A newly focused page link can be scrolled clear once. Later scroll/resize events never pull the page back toward retained focus; the bar hides if it would intersect that control. The resize observer only refreshes reserved height. Dismissal or switching to desktop restores main focus when a bar control held focus. Native details navigation and direct booking links work without JavaScript. Shared English content on Portuguese pages is marked; Portuguese links and sticky labels use pt. Clinical facts, prices and content claims are unchanged pending the owner's M3 review.

Explicit `tabindex="0"` is limited to header/navigation, footer and reminder links, matching the existing navigation pattern and the observed default WebKit tab order. In-content CTA and article links retain native anchor behaviour. In Safari on Mac, Option-Tab includes links; users can change the Advanced keyboard-navigation setting so Tab includes all page items. This browser preference is documented by [Apple](https://support.apple.com/en-gb/guide/safari/cpsh003/mac). The browser tests assert the distinction in default WebKit and verify content links remain focusable. This is a documented browser difference, not a claim that every content link has explicit tabindex.
